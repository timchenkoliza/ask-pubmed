# Спросить PubMed — прототип

Прототип поиска по PubMed для врачей: запрос своими словами → как поняли → выдача с объяснением.
Все публикации, журналы, счётчики и PMID вымышленные.

```
npm install
npm run typecheck
npm run build     # пишет public/index.html (для Vercel) и dist/index.html
```

`public/index.html` лежит в репозитории готовым: Vercel ничего не собирает, только раздаёт каталог `public`.
После правок в `src/` пересоберите (`npm run build`) и закоммитьте `public/index.html`.

## Что умеет прототип

Задача врача определяет вид выдачи, а не наоборот: `запрос → job → понятия → условия → варианты запроса → слияние → ранжирование → состояние → вид`.

| Задача врача | Вид |
|---|---|
| найти публикации | сетка публикаций |
| узкая подборка («в приоритете», «по годам») | сгруппированная выдача |
| сравнить два подхода | сравнение: прямые сравнения отдельно от публикаций, где упомянуты оба |
| найти факт в публикации (PMID, DOI, название) | публикация с поиском по тексту |
| найти цитаты | цитаты (только из доступного текста) |
| вывод по исследованиям | найденные публикации и передача в Deep Research |
| ничего не нашли | экран с составом запроса и тем, что помешало |
| два и больше правдоподобных смысла | уточнение |
| запрос не превратился в поиск | экран «не поняли» с причиной: нет слов, тема не из прототипа, две темы сразу, несколько номеров публикаций |

## Что в прототипе только показано

- Данные локальные: вместо PubMed API работает `src/data/backend.ts` с тем же интерфейсом ответа.
- Deep Research и переход в рубрикатор клинических рекомендаций не подключены: интерфейс показывает, что и куда ушло бы, и прямо говорит об этом.
- Срок публикаций считается в годах назад от текущего года. Точный год или диапазон («за 2024 год», «2020–2022») читается как «с этого года до сегодня».
- Цитаты по корпусу есть не для всех тем: если фрагментов нет, прототип так и пишет и показывает обычный список.
- «Не найдено» по PMID, DOI и названию проверяется по данным прототипа, а не по настоящему PubMed.
- Перевод на русский — готовые тексты, не машинный перевод на лету: названия, abstract, предложения-доказательства и разделы статьи лежат в `src/data/translations.ts` и в `titleRu` / `abstractRu` публикаций. Переключатель «Оригинал / Перевод» меняет всё сразу: карточку, цитату, статью, поиск по тексту и подсветку.
- Карточки не меняют размер при переводе: оба языка лежат в одной ячейке (`BiText` в `src/components/Card.tsx`), показан один, а второй держит высоту невидимым.
- Тема запроса определяется по ключевым словам пяти демо-тем: у каждой есть «ядро» (СИОЗС, GBS, диеногест, ОРВИ, железо вместе с сердечной недостаточностью) и «контекст» (беременность, кровотечение, у детей, контрацептивы). Две темы сразу («кровотечение при беременности», «ОРВИ у беременных», «железо при беременности») прототип не склеивает и не выбирает за врача: на их стыке публикаций нет, он так и говорит. Если тема названа только контекстом («заболевания щитовидной железы при беременности»), берётся ближайшая тема, а что именно понято, видно в «Как искали».
- Отрицание типов исследований читается: «без РКИ», «кроме обзоров», «не мета-анализы», «без метаанализов и РКИ» исключают тип из выдачи, «не только РКИ» — нет.
- Несколько номеров в одном запросе («PMID 1, PMID 2») открываются по одному: прототип предлагает выбрать. Ссылки pubmed.ncbi.nlm.nih.gov/… и doi.org/… читаются как номера.
- Цитаты и сравнение есть не для всех тем. Если врач просил то, чего для темы нет, выдача обычная, а над ней сказано, чего нет.
- Режим агента, выход из него и переходы в ПБЗ, Ленту и калькуляторы в прототипе пока не показаны: ждём выбора варианта сквозного сценария.
