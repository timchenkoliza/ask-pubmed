# Спросить PubMed — прототип

Прототип поиска по PubMed для врачей: запрос своими словами → как поняли → выдача с объяснением.
Все публикации, журналы, счётчики и PMID вымышленные.

```
npm install
npm run typecheck
npm run build     # пишет public/index.html (для Vercel) и dist/index.html
```

`public/index.html` лежит в репозитории готовым: Vercel ничего не собирает, только раздаёт каталог `public`.
После правок в `src/` пересоберите (`npm run build`) и закоммитьте `public/index.html`.

## Что умеет прототип

Задача врача определяет вид выдачи, а не наоборот: `запрос → job → понятия → условия → варианты запроса → слияние → ранжирование → состояние → вид`.

| Задача врача | Вид |
|---|---|
| найти публикации | сетка публикаций |
| узкая подборка («в приоритете», «по годам») | сгруппированная выдача |
| сравнить два подхода | сравнение: прямые сравнения отдельно от публикаций, где упомянуты оба |
| найти факт в публикации (PMID, DOI, название) | публикация с поиском по тексту |
| найти цитаты | цитаты (только из доступного текста) |
| вывод по исследованиям | найденные публикации и передача в Deep Research |
| ничего не нашли | экран с составом запроса и тем, что помешало |
| два и больше правдоподобных смысла | уточнение |

## Что в прототипе только показано

- Данные локальные: вместо PubMed API работает `src/data/backend.ts` с тем же интерфейсом ответа.
- Deep Research и переход в рубрикатор клинических рекомендаций не подключены: интерфейс показывает, что и куда ушло бы, и прямо говорит об этом.
- Срок публикаций считается в годах назад от текущего года. Точный год или диапазон («за 2024 год», «2020–2022») читается как «с этого года до сегодня».
- Цитаты по корпусу есть не для всех тем: если фрагментов нет, прототип так и пишет и показывает обычный список.
- «Не найдено» по PMID, DOI и названию проверяется по данным прототипа, а не по настоящему PubMed.
